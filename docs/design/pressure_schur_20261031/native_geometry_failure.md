# A2 packed-geometry setup failure: source audit

Read-only audit of frozen worktree `899517260a5c045f753008216005e64908106d55` and the failed `a2_numerical_diagnostic/run/runs/candidate/rsl.error.0000`. The selected process reached the exact baseline preflight digest `7bdd17f3a694726e` but stopped at factory setup with `native pressure reference grid metadata do not identify the packed physical core`. No P0 application, GMRES comparison or completed timestep resulted.

The source-supported cause is the factory's **grid symmetry flags**, not evidence that its dimensions or domain endpoint convention are wrong. The failing factory first requires `geometry.whole_single_rank && geometry.packed_periodic_x_symmetric_y` and proceeds past that check, the packed stagger-dimension check, all six unit-map checks, and flat ground check before the later compound assertion. At the original EOS call `tile_unified_impl.cpp:20420–20434`, `geometry.packed_periodic_x_symmetric_y` is captured directly from `isPackedPeriodicDomain()`.

`isPackedPeriodicDomain` (`:15254–15270`) uses the actual tile solver's effective boundary flags and requires all of the following: one rank, no AD halo, periodic X, nonperiodic symmetric Y at both walls, no open/specified/nested boundaries, exact `grid_info_->its==ids`, `ite==ide`, `jts==jds`, `jte==jde`, `nx_==ide−ids+1`, `ny_==jde−jds+1`, and stagger dimensions `nx_u_==nx_+1`, `ny_v_==ny_+1`. A true captured predicate therefore already establishes those exact conditions at capture. It does not check `config_flags_polar_` and that condition must be captured separately or explicitly added to the attested predicate.

The Fortran bridge obtains its/ite/jts/jte from the tile and sets `nx=ite−its+1`, `ny=jte−jts+1`, `nx_u=nx+1`, `ny_v=ny+1`, `nz_w=nz+1` (`dyn_em/module_implicit_sdirk3.F:652–692,1248–1305`). The per-call v2 ABI validates those dimensions before forwarding its/ite/ids/ide and peers through `setWRFIndices` (`wrf_sdirk3_interface_zerocopy.cpp:550–563`); that setter copies tile/domain bounds and stagger sizes into `grid_info_` (`tile_unified_impl.cpp:32898–32997`). The tile constructor and `grid_info_` receive the same nx/ny (`:3504,3866–3877`). The failed run logs `WRF TILE 1 IS 1 IE 41 JS 1 JE 81` and the native BC receipt `proc_grid=1x1`, effective periodic X and symmetric Y at both ends, no open/specified/nested boundaries (`rsl.error.0000:26–28,144–148`). Together with the already-passed captured packed predicate, those observations support endpoint-inclusive packed nx=41/ny=81 and independent physical mass dimensions 40×80. They do **not** support replacing the exact bound checks with `ide−1`/`jde−1` checks.

The later factory assertion (`wrf_sdirk3_native_pressure_reference.cpp:65–69`) asks additionally for `grid_info_->symmetric_ys && grid_info_->symmetric_ye`. `WRFGridInfo` initializes both false (`wrf_sdirk3_types.h:345–350`). The actual boundary setter saves and resolves all effective flags on the tile but synchronizes **only** `periodic_x` and `periodic_y` into `grid_info_` (`tile_unified_impl.cpp:32620–32664`); repository search finds no production assignment to `grid_info_->symmetric_ys/ye`. The BC receipt above demonstrates the class-effective Y flags are true, not that these grid-cache fields were synchronized. They are therefore stale false under this construction. The failing log does not print each individual conjunct, so the exact runtime field values were not independently logged; this is a source-backed causal diagnosis rather than a per-field runtime dump. Red independently reached the same conclusion.

## Narrow correction and authoritative boundary contract

The subsequent source fix sets the existing same-call capture attestation to `isPackedPeriodicDomain() && !config_flags_polar_`. The factory uses that actual tile predicate as the single authority for effective boundary flags, rather than repeating unsynchronized `WRFGridInfo` BC fields. The separate `whole_single_rank` check, exact grid bounds/extent/stagger checks, and all captured unit-map, flat-ground, live/raw metric, state-binding and positive-coefficient checks remain. This does not remove geometry validation, weaken endpoint bounds, trust an arbitrary external flag, mutate global configuration, or establish unsupported halo behavior.

The focused regression leaves grid symmetry at its false defaults while a valid captured attestation is true, and includes false-attestation and inconsistent-bound negatives. It also exercises the actual Tile EOS capture with its effective polar flag toggled. Nonunit maps, nonflat ground and missing rank evidence retain their existing negative checks. Results are recorded separately after the focused run. This is a setup-contract fix only: native P0 solve, actual A−P0 residuals and performance remain untested; no model rerun was performed for this correction.
