# Red audit: boundary for repeated live Tile JVP cost

Local time: 2026-11-01 23:30:49 JST
Source audited: `0c3f2fa6db7fe500e17550e90d966d7ba074098f` in `/private/tmp/frozen-jvp-cost-20261101`. This is a source audit, not a model run or a same-setup RK3 field/runtime comparison.

The proposed observation is stage 4, Newton iteration 0 (the fifth solve). Holding the linearization point and direction fixed is necessary but does not by itself establish either the same effective operator or an unchanged continuation. The source exposes mutable Tile and process/thread-local state; no complete, exception-safe live-state restore facility has been established here. This is not proof that repeated calls change numerical results or branch paths in the current gated profile.

## Source boundary

- [`compute_rhs`](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L14115) selects the split and fixed forcing, then calls the Tile RHS. The optional `omega_update_ref_per_newton` branch replaces `U_ref_stage_` with a clone of its input. The RHS reads that reference for `w_ref` ([source](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L15682)). If enabled, the reference and its AD relationship are part of the operator contract. The [A9 selected record](../../evidence/linear_delay_audit_20261101/candidate_selected_log.txt#L5) reports this flag off and zero reference handle/version changes; the branch is a general risk, not an observed A9 cause.
- The RHS writes [`grid_info_->dt` and, at debug level 2 or higher, mask counters](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L15580), and initializes or replaces [tendency tensors](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L16149). Its [pressure diagnosis publishes `p_pert_`](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L20516), used by V/W pressure-gradient paths and write-back. The A9 selected record reports changes to `p_pert_work`, `dpx_work`, `cqv_at_v_work` and other scratch handles or versions. These observations do not themselves prove a mathematical operator change; they do make continuation restoration and interpretation of repeated timing nontrivial.
- The RHS can refresh [map factors](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L16425) and align [base-state tensors](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L16520). It also uses [thread-local map cache state](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L16589) and [a second cache](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L17248). A warm cache can change cost without changing results. The full-halo path additionally requires a [valid neighbor cache](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L40989) and re-enters the interior RHS.
- The existing diagnostic guard [restores reference and timestep but explicitly acknowledges other mutations](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L6890). Its fingerprint is a detector, not a complete restoration or proof of noninterference. [`withPreparedRhsCleanup`](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L15363) detaches selected graph owners; it is not a full state restore.
- [`PreparedJvp`](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_jvp_autograd.cpp#L14) evaluates the RHS once during preparation and applies a retained reverse-over-reverse graph thereafter; apply does not re-enter Tile RHS. Its application time is therefore **not repeated native forward-mode JVP cost**. The production reuse path has [strict profile gates](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_tile_unified_impl.cpp#L14094), checks [primal and forward-mode derivative agreement](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_newton_solver.cpp#L9293), and [invalidates the retained graph on interleaved RHS calls](../../../external/libtorch_wrf/sdirk3/wrf_sdirk3_newton_solver.cpp#L5055).

## Smallest sound next experiment

1. Prefer a narrowly scoped isolated evaluator that reconstructs the exact supported Tile context from verified inputs, without modifying the live solver. Establish ownership and cache isolation rather than assuming a shallow copy suffices. Run fixed-point, fixed-direction native forward-mode JVPs there and report initialization, first-call and steady-state costs separately. Do not assume a process fork after LibTorch initialization is thread-safe or an isolation mechanism.
2. Alternatively, make a terminal diagnostic explicitly labelled as such: repeat only after the last result needed from the live run, do not resume the solve, and report its context and cache state. This can characterize native calls but does not prove noninterference with a continuing solve.
3. PreparedJvp preparation and application can be measured separately as a different method, with its supported profile and correctness checks. Do not substitute those timings for native forward-mode calls.

No giant live-context snapshot is proposed. A restore-based live experiment remains unestablished until all relevant mutable state and exception paths are proven safe.

## Gates before any native repeat

- Identify the exact source/executable, stack, stage/iteration, rank/tile topology, split mode, dtype/device, halo state, and effective A9 flags, especially `omega_update_ref_per_newton`; capture the fixed reference, base fields, forcing, timestep and boundary context. Gate out unsupported or uncertain configurations.
- Capture detached fixed `U` and the actual physical `v`, require matching shape/dtype/device, finite inputs and a nonzero direction. Ensure the intended AD/reference semantics are unchanged. Reject if context, tensor values or relevant versions change unexpectedly.
- Compare repeated primal and tangent results against the original native forward-mode evaluation, with stated tolerances and finite checks; reject on mismatch, exception, fallback, or unexpected path/counter changes. Equality is necessary evidence for this sample, not proof for all states.
- For a live continuation, prove restoration of every relevant state and cache on normal and exceptional exits before executing; otherwise use isolation or terminal observation and do not claim continuation parity.
- For P0/P1 comparison, hold the same captured linear operator **A**, right-hand side **b**, initial iterate, scaling, preconditioner context and stopping rule; verify them and compare true residuals and solution behavior as well as cost. Do not infer a same-A, same-b comparison from matching labels or stage numbers.
