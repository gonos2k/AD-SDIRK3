# Stage-operand history diagnostic on the hybrid tile

Timestamp: 2026-09-24 18:15:06 JST (+0900)

## Context and root cause

This candidate starts from PR #217 head `a8b1a9f1eee10010a8ccf032b3a3242de2af8d57`. The new nonuniform-hybrid tile completed normally, but enabling the existing `stage_operand_diag` aborted before its accepted-stage test could finish: `SDIRK3_STAGE_OPERAND_CLOSURE_FAILED`, `hist_rel=1.523801e-6`, `hist_max_abs=3.649131e-7`, `hist_max_rel=6.595695e-3`. This is an O1 diagnostic failure, not by itself proof of a production ARK history error.

Production `ark324_stage_base` forms `dt*a` in double precision and then applies that scalar to the stage tensor, updating a running FP32 state after each source. The history emitter and its nominally bit-exact per-source attribution check previously formed `float(dt)*float(a)` before tensor multiplication. Correcting that scalar order alone did not remove the hybrid failure: the aggregate emitter also summed rounded source increments in FP64, while the actual endpoint contains each intervening FP32 state addition. An ideal sum can therefore differ from a correct rounded endpoint by more than a fixed `1e-6` fraction of the small history norm.

The diagnostic now matches production's double scalar formation in **both** paths. It retains the original strict FP64 history ratio as the first check. If that ratio is exceeded on an FP32 state, it accepts only a bit-exact sequential FP32 replay of the same captured source tensors and coefficients; non-finite values and the existing local `hist_max_rel` gate still fail. The later per-source gate independently replays every captured intermediate state with exact equality. No production tableau, stage equation, solver tolerance, or forecast RHS was changed.
