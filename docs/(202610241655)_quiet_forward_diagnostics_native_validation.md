# 일반 전방의 진단 출력·계측 OFF, 자료동화 기록은 명시적 요청으로 유지

최종 갱신 시각: 2026-10-24 17:00:23 JST (UTC+09:00)

일반 전방 계산에서 불필요한 JVP 진단 출력과 계측을 생략하도록 수정했다. 필요한 JVP 수치연산은 유지한다. 자료동화용 그래프·궤적 기록은 기존 `retain_graph_for_adjoint`, `save_trajectory` 및 명시적 고정궤적 요청/종료 경로를 사용하며, `use_autograd`를 켰다는 이유로 활성화하지 않는다.

최종 재빌드로 수행한 공식 규모 `em_b_wave`의 RK3·ARK 6시간 계산이 모두 정상 종료했다. **시작·6시간의 네 NetCDF 파일 전체가 각 방법의 기존 결과와 바이트 단위로 일치**한다. 각 프레임의 숫자 변수 174개, 차원·자료형·비숫자 변수·전역 속성도 확인했다. 두 실행 모두 점검한 40종 진단 문자열이 0행이다.

## 실행 시 선택

일반 전방의 기존 설정을 다음처럼 사용한다. `test/em_b_wave/namelist.input`도 이 두 출력 설정만 변경했다.

```fortran
sdirk3_debug_level = 0,
sdirk3_solver_telemetry = .false.,
```

- `solver_telemetry=true`를 명시하면 집계된 Newton/JVP 진단을 수집한다.
- `debug_level=2`에서 JVP·FD·FWAD의 상세 노름·접선 진단을 활성화한다.
- 자료동화 기록은 별도의 기존 `requestFixedTrajectory`/`beginFixedTrajectory`와 `closeFixedTrajectory`, 지원되는 retain 설정으로 필요한 구간에만 요청한다. 일반 전방은 이 요청을 하지 않는다.
- 필수 수렴·비유한값·halo 검사와 복구는 유지한다. 이상값·실패 경고, WRF의 기본 예측 출력·진행·초기 설정·종료 통계는 해당 기존 경로에 남는다.

새 옵션이나 ABI를 추가하지 않았고, 풀이 중 JVP 모드나 전역 설정을 변경하지 않는다.

## 변경한 코드

`wrf_sdirk3_newton_solver.cpp`는 Newton 보정마다 기존 `solver_telemetry || debug_level>=1`을 읽어 진단 수집 여부를 결정한다. OFF에서는 개별 JVP 시계를 읽거나 시간을 합산하지 않는다. 중첩된 AD 시간 측정도 요청된 디버그 출력에 한정한다. JVP·FD 상세 노름과 정상 Newton/GMRES 성공 출력도 기존 진단 조건에 묶었다. 필요한 호출 순번·FD 선택/잠금·epsilon·INN·실패 판정은 유지한다. 계측하지 않은 예외 경로는 0 ms 대신 `timing disabled`로 표시한다.

소스 검토에서 발견한 반환값 문제도 한 줄로 바로잡았다. 진단 OFF 성공 경로는 실제 잔차를 `stats_.final_residual`에 이미 측정하면서 `NewtonResult.final_residual`에는 초기값 0인 출력용 임시값을 반환했다. 이제 이미 측정한 통계값을 반환한다. 수렴 판정식과 허용오차는 바꾸지 않았다.

`wrf_sdirk3_tile_unified_impl.cpp`는 FWAD 접선 확인 세 블록과 FP64 상태 전달 메시지를 조건부로 실행한다. Halo 최댓값은 실제 이상값 복구 판정에도 사용되므로 **계산과 복구를 그대로 유지**했다. 같은 `repair_halos` 조건을 복구와 이상값 표시에 사용하며, 정상 halo 값 출력만 상세 디버그에 한정한다.

`module_implicit_sdirk3.F`와 `solve_em.F`는 격자·지도계수·연직 좌표·초기화 전후·단계 진입·JVP 방법의 디버그 메시지를 기존 출력 수준에 묶었다. 형상 계산, 초기화·기본장 설정 호출, config setter, workers 시작, 오류·정리·종료 통계는 조건 밖에 둔다. 생성된 Fortran 파일을 수정하지 않고 `.F`에서 다시 전처리·컴파일했다.

## 단위·수반 검증

새 `Solver_Diagnostics_Noninterference` 검사 **24/24**가 통과했다.

- AD와 고정 전방 FD의 진단 OFF/집계 ON/상세 디버그에서 K·수렴·반복수·반환 잔차 일치
- 집계만 켠 `debug=0`에서 상세 JVP/FD 노름 출력 부재
- 같은 캐시 이력을 가진 솔버의 ON→OFF와 OFF→OFF 결과 일치 및 OFF 복귀
- 비유한 RHS가 조용한 모드에서도 실패하고 오류를 표시함
- 실제 WRF TileCase의 FWAD 진단 활성화와 상태 불변

기존 `FGMRES_Contract`와 `Fixed_Trajectory_Derivative`도 통과했다. 최종 Tile 변경 후 고정궤적 수반 검사를 같은 v2 C++ 아카이브로 다시 확인했다. 새 CMake 시험 항목을 등록했고, 로컬 검증은 동일 생산 아카이브·헤더·libtorch/MPI로 직접 빌드·링크한 시험 실행이다. 전체 CTest나 GitHub CI를 새로 실행했다고 주장하지 않는다.

초기 20/21 실패 기록은 보존한다. 해당 검사는 같은 솔버의 첫 호출과 캐시가 채워진 두 번째 호출의 반복수까지 같아야 한다고 잘못 요구했다. 두 호출의 K와 잔차는 같았고 반복수만 4→1이었다. 올바른 대조는 같은 호출 이력을 가진 두 솔버의 첫 호출끼리, 두 번째 호출끼리 비교하는 것이다. 이를 엄격한 결과·반복수 일치 조건으로 수정해 통과했다. 생산 캐시·warm-start 동작은 바꾸지 않았다.

## 실제 native 6시간 대조

이전 [표준 사례 6시간 근거](<(202610241427)_standard_ark_six_hour_screen.md>)와 같은 초기장·40×80×64 질량 격자·100 km·600초 간격·건조 물리·확산·경계·출력 주기를 사용했다. 새 RK3 실행은 공통 Fortran 출력 정책 변경 후 같은 6시간 비용을 맞추기 위한 것이다. 기존 참값 생성과 작은 240초 수반·복원 실험은 재실행하지 않았다.

| 항목 | RK3 | ARK324 |
|---|---:|---:|
| 모델시간·스텝 | 6시간·36 | 6시간·36 |
| 종료 코드 | 0 | 0 |
| 점검한 40종 진단 출력 | 모두 0행 | 모두 0행 |
| 기존 시작·끝값 파일 | 전체 바이트 일치 | 전체 바이트 일치 |
| 프레임별 숫자 변수 | 174개 유한값·일치 | 174개 유한값·일치 |
| 전체 경과시간, 단조시계 | 6.656076초 | 2,027.693202초 |
| RSL main-step 시간 합 | 4.566760초 | 2,024.439180초 |

ARK의 전체 경과시간은 약 **33분 48초**다. 같은 6시간의 측정 비는 단조 경과시간 기준 **304.64배**, RSL 적분 구간 기준 **443.30배**다. 전체 경과시간에는 런처·초기화·I/O·감시기의 종료 감지 지연이 포함되며, 특히 짧은 RK3 실행에서는 그 비중이 크다. 한 번씩의 관측이며 동일 정확도 속도비나 반복 실행의 시간 분산을 인증한 값이 아니다. 출력 제거 후에도 현재 ARK 전방 비용은 RK3보다 매우 크다.

원래 ARK 진단 ON의 단조 경과시간은 2,318.070156초였다. 이번 값은 그보다 작지만, 재빌드·실행 시점·하드웨어 부하 등의 영향을 분리하지 않았으므로 차이 전체를 출력·기록 비용으로 단정하지 않는다. 이번 실행에서는 JVP 계측을 껐으므로 새 JVP 호출수·시간·Newton 반복 통계를 만들어 보고하지 않는다. 종료 통계의 108/0은 **Fortran wrapper 호출/실패 수**이며 독립적인 Newton 단계 계수가 아니다.

ARK의 wall-clock 차이값은 2,025.785838초, 단조시계 경과값과의 차이는 약 −1.907초로 기존 5초 한도 안이다. 비용 표와 전체 경과시간 비에는 단조시계를 사용했다. 두 시계 차이의 원인은 별도로 규명하지 않았다.

정상 종료, 소유 프로세스 정리, 두 출력의 양의 총 온위·기둥질량·층두께·총압을 확인했다. 새 RK3–ARK 장 거리는 이전과 동일하다. 예를 들어 6시간 W RMS 거리는 1.189469396e-4 m/s다. 이는 방법 간 거리이고 RK3 참값 오차가 아니다. 5일 ARK 완주·시간간격 민감도·새 물리 정확도 예산은 계속 별도 미완료 항목이다.

변경한 네 생산 파일을 같은 도구 스택으로 재빌드하고 아카이브의 해당 멤버만 바뀌었음을 검사했다. 이전 실행파일과 결과는 보존했다. 공통 종료 관찰 코드는 기존 query-free 계측 소스 리비전에서 이어지며, 정확한 소스·객체·라이브러리·링크 해시는 근거에 있다. ABI·헤더 변경은 없다. Graphify의 소스 핀과 변경 후 C++ 그래프를 확인했고, 지원되지 않는 Fortran AST는 원문 호출·분기 검사로 보완했다.

이번 작업의 WRF native 시도는 총 세 번이다. 첫 시도는 JVP 진단 제거 뒤 남아 있던 다른 디버그 출력을 발견해 3스텝에서 소유 프로세스를 정리하며 중지했다. 원래 RC1과 중지 사유를 남겼고 수치 실패나 유효한 성능 표본으로 사용하지 않는다. 이후 최종 소스의 RK3·ARK 두 6시간 실행이 각각 RC0으로 완료했다. 비정상 종료를 결과 파일만으로 수용한 사례는 없다. 이번 정상 MPI 종료도 과거 R1 원인 규명을 뜻하지 않는다.

[변경·실행 근거와 재검산 안내](evidence/quiet_forward_diagnostics/README.md)에 소스 변경, 단위 검사, 빌드·런처·종료 로그, 원배열 일치와 비용 통계가 있다. 원배열 파일은 기존 근거 ZIP의 내용과 SHA-256이 같아 중복 저장하지 않고 참조한다. Green·Red 팀이 실제 파일과 결과를 독립 확인했다.
