# 종료형 native JVP 반복 진단 — 실행 전 고정 범위

작성: 2026-11-02T00:21:46.470573+09:00.
기반: main036748f2(PR336 병합). Green·Red: GPT-6.1-Terra, medium.

이번 산출물은 실제 stage4/Newton0 첫 Arnoldi 방향의 원래 forward-AD JVP 반복
값·호출비용이다. P0/P1 비용 수용·전체 가속·잡음 치료·정상 예보 완료를 판정하지 않는다.
같은100km·40×80×64·600초·FP64 입력/기준 경로로 원래 초기장에서 시작한다.
기존 RK3 초기장을 재사용하며 새 RK3/시간간격 축소/장시간 실행을 추가하지 않는다.

- native 실행은1회만 허용하며 재시도하지 않는다. 실제 ordinal5/timestep0에서 원래1회와
  추가 최대5회를 측정한다. 입력·문맥·경로가 안전하지 않거나 예외가 나면 남은 반복을 중단한다.
  단순 출력 불일치는 고정 반복의 범위에서 기록한다. 유리한 결과가 나올 때까지 반복하지 않는다.
- 원래 RHS wrapper와 compute_jvp_forward_mode/router를 그대로 쓴다. 원래 dual 평가의
  primal을 선택적으로 받아 별도 RHS 호출을 만들지 않는다. PreparedJvp로 대체하지 않는다.
- 원래 primal/tangent를 복제해 고정하고 반복 결과의 형상·FP64·유한값·바이트 일치,
  최대 절대/상대차를 확인한다. U/v 값·고정 문맥의 관측 부분·참조 상태를 비교한다.
  모든 호출은 RHS1회/native forward AD/fallback0이어야 유효하다. 비유한값·예외는 실패다.
- CPU는 process user+system, wall은 steady clock으로 같은 호출을 감싼다. primal 복제,
  입력 해시·문맥 검사·출력 차이 계산·JSON 저장은 호출시간 밖이다. 검사 자체가 cache를
  준비할 수 있으므로 반복 비용은 그 조건을 포함한 값이다. 첫 표본은 해당 선택점의 원래
  호출이며 프로세스의 cold 첫 RHS라는 뜻이 아니다. 평균·중앙값·범위·CV는 기술 통계로만 보고한다.
- 실제 Torch intra/inter-op1/1, MPI1rank·dry mode3·고정 참조 갱신OFF 지원 profile만 허용한다.
  소스·실행파일·입력·스택·실행 스크립트를 빌드·실행 전에 해시 고정한다.
- JSON과 명시적 marker를 쓰고 정상 진단86/실패87로 프로세스를 즉시 종료한다. 원래 solve를
  재개하지 않는다. wrapper 통계/종료코드0/완료 예보/상태 재시작 근거를 만들지 않는다.
  네 개의 이전 선형계가 끝났더라도 대시간스텝 완료는0이다.
- 자원은 실행 전후 가용공간5GiB, rank 사후 최고RSS4GiB, MPI360초 watchdog,
  wrapper390초 상한을 사용한다. 주기적 전역ps/lsof·대형 graph·반복별 배열 덤프는 추가하지 않는다.
  RSS 사후값을 실시간 전체시스템 보장으로 표현하지 않는다.

생산 옵션/시간맵/감쇠/허용오차를 바꾸지 않는다. 진단 macro는 기본 비활성이다.
공유 inline header의 primal-out API를 참조하는 네 TU는 재빌드하고 나머지는 depfile과
소스·헤더·archive member 해시를 확인해 재사용한다. 기존 class/Fortran ABI는 변경하지 않는다.
집중시험, 원래 경로의 CI, 실제 한 번의 종료형 실행은 서로 다른 범위로 기록한다.

관측 문맥은 전체 Tile 직렬화나 복원 계약이 아니다. 작업 버퍼의 허용된 갱신과 warm cache는
남기며, 원래 적분을 계속하지 않아 전체 복원을 선행조건으로 추가하지 않는다.
결과로 반복 값과 비용의 분포를 확인한 뒤 같은A,b,x0,S P0/P1 비용 비교를 다음 단계로 판단한다.
