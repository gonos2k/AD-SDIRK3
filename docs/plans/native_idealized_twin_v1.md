# Native 이상화 쌍둥이 실험 계획 v1

작성 시각: 2026-10-22T05:16:23+09:00 (JST).

상태: **계획 등록, 미실행**. 수치 설정의 단일 기준은
[`native_idealized_twin_v1.json`](native_idealized_twin_v1.json)이다.
이 JSON은 계획 스키마이며 solver가 읽는 실행 설정이나 실행 완료 기록이 아니다.

## 목적과 완료 범위

검증된 native 시간맵을 알려진 초기 오차의 추정에 사용하는 별도 사례다.
참상태 → 합성관측 → 오차 초기장 → 관측 잔차 → 수반 → 최소화 → 초기 제어와
비사용 상태 복원까지 연결한다. 실관측 제공을 착수 조건으로 두지 않는다.
[WRF 공식 문서](https://www2.mmm.ucar.edu/wrf/users/wrf_users_guide/build/html/idealized.html)는
`em_b_wave`를 이상화 사례로 분류한다. 여기서 참값은 선언한 이산 모델의 수치
참값이다. 실제 대기의 정확도나 실관측 자료동화 성능을 인증하는 실험은 아니다.

PR #314의 두 진단량 합성 잔차 검사는 완료로 유지한다. 완료된 회전파 역문제를
다시 실행하는 계획도 아니다. E0·E1·E2가 아래 기준을 충족하면 이 새 제한 사례를
종료한다. 잡음, 배경항, 습윤, 지형, 다중 MPI, 배포는 사후 필수 조건이 아니다.

## 유지할 시간맵과 참값

[`dry_em_b_wave_e71_240s_h15over16_strict_v1`](../evidence/research_forward_setting/research_forward_map.json)를
그대로 사용한다. 건조 물리 격자 16³, 240초, `h=0.9375 s`, 256스텝,
Newton 절대/상대 `1e-9/0`, Krylov `1e-7`, 유효 EWT `1e-6`, CPU 한 rank·한 tile이다.
수송·확산·감쇠·CF·경계, 내부 FP64 연속 전달을 유지한다. 제어점은 초기화와 CQ가
끝난 solver 진입 상태이며 입력 파일의 초기화맵 미분을 추가하지 않는다.

원래 상태를 `Z*`, 궤적을 `Zn*=G(0→n)(Z*)`로 둔다. 보존된 FP64 수용 상태가 현재
생산 소스·실행파일의 검증된 전방 중립성, 입력·옵션·수치 보조상태 정책과 연결되면
재사용한다. 연결을 입증하지 못할 때만 참값 전방 한 번을 수행한다. 상태 파일만
읽는 cold restart로 수치 이력을 대체하지 않는다. 자료·실행파일·옵션·제어 모드의
해시를 실행 전에 고정하며, FP32 history 출력으로 작은 섭동 관측을 만들지 않는다.

## 관측과 비용함수

관측 시각은 수용된 128·256스텝(120·240초)이다. 각 시각의 U, V, 건조 총 온위
`theta=T+300`에서 각 축 `{2,6,10,14}`의 곱집합을 선택한다. **1부터 세는 물리
소유 영역의 순번**이며, halo나 packed 배열의 직접 인덱스가 아니다.
U는 고유 주기 X면, V는 물리 Y면, theta는 질량점을 기준으로 각각 매핑한다.
각 변수 64개 × 세 변수 × 두 시각 = **384개**다. destagger나 보간을 추가하지 않는다.

목록 순서는 시각, 변수 `[U,V,theta]`, `k,j,i`(i가 가장 빠름)이다. 각 행에 고유 ID,
수용 스텝·초, 변수·stagger·단위, owner 순번·전역 인덱스·packed 슬롯, 그 stagger의
수평 물리 좌표·연직 좌표를 저장한다. 좌표·슬롯은 일치하는 runtime grid/layout에서
생성한다. U/V의 같은 순번을 같은 물리 위치로 취급하거나 주기 중복면을 넣지 않는다.

관측 `y=H(Z*)`는 위 FP64 참궤적에서 만든다. 핵심 실험은 잡음 0이며
`sigma_U=sigma_V=0.05 m/s`, `sigma_theta=0.01 K`, `R=diag(sigma²)`로 고정한다.
이 값은 연구용 단위·크기 가중이며 실제 관측오차 추정이나 예측 예산 epsilon이 아니다.

\[
J_o(a)=\frac12\sum_{n\in\{128,256\}}
  \|R_n^{-1/2}(H_nG_n(Z_0(a))-y_n)\|_2^2,\qquad J_b=0.
\]

합을 관측 수나 시각 수로 다시 평균하지 않는다. 각 평가점에서 잔차를 새로 계산하고
`q_n=H_n^T R_n^{-1}r_n`을 해당 수용 endpoint에 한 번 주입한다. theta의 상수
300 K는 관측과 참값에 동일하게 적용하고, 전치에서는 선택 슬롯으로 scatter-add한다.
초기 기울기는 `g_a=P^T lambda0`다. `P`는 경계 확장을 포함한 실제 packed 제어
모드이므로, 투영할 때 별도의 owner 마스크로 alias 기여를 다시 버리지 않는다.
기존 FP32 cotangent 경계와 구간별 checked pullback을 사용할 경우 그 정밀도를 기록한다.

## 두 초기 제어

제어 순서는 `[wind,theta]`다. `P=[p_wind,p_theta]`를 고정하고

\[
Z_b=Z_*+0.5p_{wind}-0.5p_\theta,\qquad
Z_0(a)=Z_b+a_1p_{wind}+a_2p_\theta
\]

로 둔다. 시작점 `a_b=(0,0)`, 제어범위 `[-1,1]²`, 참 제어값 `a*=(-0.5,+0.5)`이므로
`Z0(a*)=Z*`다. 참 제어값은 E1 최소화의 입력·정지·갱신 규칙에 쓰지 않고 최종 복원
검증에만 쓴다. FP64 표현에서 실제 생성된 `Zb`, `P`, `Z0(a)`와 경계 확장을 함께 고정한다.

모드 생성의 수학적 정의는 다음과 같다. `Lx=16 dx`, `Ly=16 dy`, `zeta_k=1-ZNU_k`다.

- C-grid 수평 꼭짓점에 `psi=sin(2pi x/Lx) sin(pi y/Ly) sin(pi zeta_k)`를 두고,
  `u_raw=-D_y psi`, `v_raw=D_x psi`를 인접 꼭짓점 차분으로 각 U/V면에 둔다.
  **두 블록의 공통** owner 최댓값으로 정규화해 최대 크기를 `0.1 m/s`로 한다.
- 질량점에 `t_raw=sin(2pi x/Lx) cos(pi y/Ly) sin(pi zeta_k)`를 두고 owner 최대
  절대값으로 정규화해 `p_theta`의 최대 크기를 `0.01 K`로 한다.
- 고유 owner 값을 먼저 생성하고 기존 경계 규약으로 주기 alias, U/theta 대칭,
  V 반대칭·벽면 정확한 0을 채운다. 나머지 블록은 0이며 W/PH 고정 하단을 바꾸지 않는다.

이 curl은 지정한 계산 격자의 차분 정의다. 실제 질량가중 발산이나 정역학·지균 평형이
0이라고 주장하지 않는다. EOS가 현재 상태의 압력을 진단하며 압력을 강제 고정하지 않는다.
생성기에서 좌표 원점·ZNU·metric·경계 매핑과 실제 모드 바이트를 확인해야 한다.

## E0·E1·E2와 동결할 판정

**E0**는 `Z0_E0(b)=Z*+Pb`, `b=(0,0)`에서 참관측을 사용한다. E1의 배경 오차가
없는 별도 영 혁신 검사다. 동일 평가·수반·최소화 경로에서 아래 세 기준을 모두 확인한다.

**E1**은 위 `Zb`와 `a_b`에서 시작하는 무잡음 복원 실험이다. 시작점 `a=(0,0)`의 관측 민감도
`A=R^(-1/2) d(HG)/da`의 384×2 행렬에서 `s_min/s_max >= 1e-3`인지 먼저 확인한다.
두 제어의 두 폭 중앙차분 관측 벡터를 재사용하며, 두 폭 모두 비율 기준을 충족해야 한다.
특이값, 열 사이 cosine,
두 폭 차이와 신호 해상도를 함께 보고하며, 미해상 rank를 통과 처리하지 않는다.
식별성 미충족이면 optimizer를 시작하지 않고 새 문제 버전으로 분리한다.

| 판정 | 기준 |
|---|---|
| E0 영 혁신 | `J<=1e-12`, `||g_b||inf<=1e-8` |
| E0 영 갱신 | `||b_final-b_initial||inf<=1e-8` |
| E1 제어 미분 | 각 축 `e1,e2`, 각 폭 `0.01,0.03`에서 FD–수반 상대차 `<=1%` |
| E1 비용 감소 | `J_final/J_initial<=1e-4`; 양의 해상된 초기 비용 필요 |
| E1 제어 복원 | `||a_final-a*||2/||a_b-a*||2<=0.01` |
| E1 최종 기울기 | `||g_final||inf/max(1,||g_initial||inf)<=1e-4` |
| E1 비사용 상태 | 아래 `E_60`, `E_180`가 **각각** 배경 대비 50% 이상 감소 |
| 허용성 | 유한값, 양의 총 온위·기둥질량·층두께, 경계 유지, 정상 단계 수용 |

두 폭은 무차원 제어 공간의 값이며, 실제 적용한 양·음 섭동과 FP32/FP64 변환을
기록한다. FD 분모는 실제 대칭 폭 `2 eta`, 상대차 분모는 `max(|FD|,|AD|)`다.
한 폭만 유리하게 선택하지 않는다. 비용 차이는 적어도
`100 eps64 max(|Jplus|,|Jminus|,|J0|)`보다 커야 하며, 실제 입력 섭동·반복풀이
변동보다 신호가 해상되는지도 확인한다. 신호나 분모가 0이면 통과가 아니라 미해상이다.

E1 최소화는 최대 **12개 수용 반복·40개 비용 전방 평가**다. 40개는 E1 최소화만의 한도다.
초기 비용과 수용·거부
line-search 비용도 40개에 포함한다. 사전 E0·두 축 두 폭 ± 평가, 필요 시 참값 한 번은
별도 집계한다. 수반을 위한 prefix 재생은 비용 전방 평가로 숨겨 세지 않고 별도 횟수·
스텝·시간을 기록한다. 사용할 기존 최소화기, box 처리·line search·기울기 호출/재생의
추가 한도는 구현 준비 시 결과를 보기 전에 고정한다. 한도 소진은 미완료이며 기준을 바꾸지 않는다.

**E2**는 관측/호출자 계층의 작은 대조로 수행한다. 0·음의 sigma/weight, 비유한 값,
중복 ID, grid/layout 불일치는 명시적으로 거부해야 한다. 수용 스텝 불일치, 중간 주입
누락·중복, `sigma²` 대신 `sigma` 사용은 기대한 cotangent와 실제 주입을 비교해
검출한다. 새 장기 전방 적분 없이 보존된 상태·잔차와 작은 H/전치 검사를 재사용한다.
두 시각 기여를 따로 검사하고, 중간 성분의 FD/수반 신호를 해상하지 못하면 전체 항의
통과로 덮지 않는다. 의도적 오류를 넣은 각각의 검사가 실제로 실패했는지 기록한다.

## 비사용 자료와 상태 복원

60·180초는 비용에 넣지 않는다. 각 시각의 전체 물리 owner U,V,W,PH,T,MU RMS 오차를
원 단위로 보고한다. U 주기 중복면·W/PH 고정 하단 제외, V 물리 벽·동적 상단 포함 등
기존 평가 영역을 유지한다. T와 theta의 상태차는 같고, MU는 총/섭동 정의를 일관되게 쓴다.

각 시각의 종합 오차는
`E_t=sqrt(sum_X[(RMS_owner(error_X(t))/s_X)^2]/6)`로 정의한다.
`s_X`는 등록된 전방 사례의 전체 예산 epsilon이며 **표시 척도**로만 쓴다.
관측 R에는 넣지 않는다. 두 시각에서 각각 `E_final<=0.5 E_background`를 요구한다.
거의 0인 개별 배경오차는 불안정한 상대 개선율 대신 절대오차로 보고한다.
종합 배경 신호 자체가 미해상이면 50% 개선으로 판정하지 않는다.
120·240초에도 각 변수의 관측 위치를 제외한 owner 오차를 별도로 보고한다.

## 실행 준비와 종료

현재는 계획만 등록했다. 실행 전에는 (1) 일치하는 참궤적/소스/실행파일과 수치 이력,
(2) 모드 생성기·P·배경·관측 384행의 좌표/슬롯/해시, (3) 최소화기와 호출/재생 예산,
(4) 모든 수용·신호/불확실성 판정의 구현·오류 검출 결과를 동결해야 한다.
이들은 실행 준비 항목이며 새 물리 사례나 사후 정확도 조건을 추가하는 허가가 아니다.

그 뒤 E0 → 식별성·제어 미분·E2 → E1 복원 → 비사용 상태 검증을 한 범위로 수행한다.
E0·E1·E2를 모두 충족하면 이 사례의 초기 제어–전방–관측–수반–최소화–상태 복원이
정상 연결됐다고 선언한다. 아직 어떤 항목도 달성 결과로 기록하지 않는다.

선택 E3는 이후 별도 버전에서만 잡음 seed와 `Jb=0.5 a^T I_2^(-1) a`를 추가한다.
잡음·사전항이 있으면 참 제어의 정확한 복원이나 `Jo=0`을 요구하지 않는다.
E3는 E0–E2 완료 조건이 아니다. 이번 계획 등록에서는 모델/재빌드/생산 코드 수정이나
새 RK3 비교를 수행하지 않았다. 기존 RK3 자료는 전방 사례의 보존 근거로 유지한다.
