# Pressure P0 native 경계 계약 수정

작성: 2026-10-31T20:56:22.271584+09:00.

## 확인된 결과와 범위

기준 소스899517의 표준100km·h600 native 기준 실행은 한 스텝·세 단계·wrapper3/0을 완료했다. RK3 초기21배열/8속성과 일치하고174개 끝값 숫자 배열은 기존 OFF와 비트 일치했다. 실제 첫 선형계는29 Arnoldi, 적용 허용오차1.0000000116860974e-7, 저장된 상대잔차1.65273217e-8이며 fallback이 없다. 이는 원래 솔버가 저장한 실제 잔차이고 독립 재계산이 아니다.

벽시계43.701197초와 단조시계41.682451초의 차이2.018746초로, 사전1초 비용 조건은 실패했다. 원래 성능 블록은 실패로 보존하며 재시도·2배 개선·Gate B 판정은 하지 않는다. 짧은 전원 로그에는 이 구간의 sleep 원인이 확인되지 않아 원인은 미확정이다.

별도 사전등록한 수치·반복수 전용 후보는 정확히 같은 문맥 지문7bdd17f3a694726e에 도달했지만, P0 생성의 경계 검사에서 종료134/0완료스텝으로 중단됐다. 원래 성능 실패를 통과시키거나 이어 붙인 결과가 아니다.

## 원인과 최소 수정

실제 Tile 경계 setter는 유효 대칭 Y를 설정하지만 WRFGridInfo에는 periodic만 동기화한다. factory가 오래된 symmetry 필드를 다시 검사하는 중복 판정이 문제였다. 같은 EOS 호출에서 얻은 실제 packed-domain 판정에 nonpolar 조건을 포함하고, factory는 그 유효 경계 판정을 재사용한다. 정확한 tile/domain 범위와 stagger/layout, unit-map·flat-ground·live/raw 상태 검사는 유지한다. 수치 RHS, ARK, 감쇠, 시간간격과 최종/선형 허용오차는 바꾸지 않았다.

대칭 grid-cache 필드가 false인 생산 형태, 거짓 실제 경계 판정, 잘못된 정확 범위, 실제 Tile EOS의 polar 전환을 검사하는 집중 회귀가 통과했고 Green/Red가 소스·binary·기록 해시를 확인했다. 이는 직접 RHS/제조 factory 검사이며 native Newton의 P0 성공은 아직 확인하지 않았다.

## 다음 작업

변경된 Tile·factory만 재빌드하고 나머지27개 객체/모든 header의 일치를 확인한다. 새 소스의 별도 수치 진단을 한 번만 사전등록해 원래 A의 잔차·guard·반복수와 여섯 예측장을 확인한다. 기존 실패 두 건은 그대로 보존하고, 비용 적격·후속 연속 실행·장기 실행 승인은 하지 않는다.

이 변경에서 새 RK3 적분은 하지 않았고 보존된 같은600초 초기/끝값 기준을 재사용했다. 새 구조의 RK3 대비 속도·24–36시간 잡음 해결·5일 정확도는 미완료다.
