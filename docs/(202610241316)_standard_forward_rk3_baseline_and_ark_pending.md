# 표준 em_b_wave 전방 비교 — RK3 기준 실행 완료, ARK 장시간 실행 대기

최종 갱신 시각: 2026-10-24 13:17:26 JST (UTC+09:00)

현재 최우선 과제는 공식 규모 `em_b_wave`에서 기존 split-explicit RK3와 native ARK324의 **전체 전방 계산 경로**를 비교하는 것이다. 기존 16³·240초 전방·수반·두 제어 복원 검사는 완료로 보존한다. 해당 결과를 600초급·5일 전방 성능의 대체 근거로 사용하지 않는다. MPI 종료 원인 조사 R1은 별도 미해결 항목으로 유지하며 이번 비교에서는 추가 R1 시험을 실행하지 않았다.

## 실행 범위와 출처

- 과학 소스 기준: `72512fc09f5f0ca7a28306b9aaad949719ef0b74`. 원래 작업 디렉터리의 사용자 변경은 건드리지 않고 별도 worktree를 사용했다.
- 공식 WRF v4.7.0 `test/em_b_wave/namelist.input`을 고정했다. `e_we=41,e_sn=81,e_vert=65`, 질량 격자 40×80×64, DX=DY=100 km, 상단 16 km, 건조 물리, 주기 X·대칭 Y, `diff_opt=1`, Kh=Kv=0, 5일 연속 적분이다.
- 같은 `ideal.exe`로 초기장을 한 번 생성했다. 종료 코드 0, `wrfinput_d01` SHA-256: `c3e56611954a5f9c1de107b7c86ecef0a5ff0ea5456cf94f26abfaf31e9bf912`.
- 공통 `wrf.exe` SHA-256: `036b86a619a5cbf79e969b3d7d8af9c612125c0d1438258c42fde501142dd497`. 시험 전용 17×17 종단 수반 caller를 제거한 ordinary build이며, 기존 query-free 종료 관찰 코드의 소스는 `dfc5ba8e3ed64a121425bda43480fabc32be8258`에서 별도로 고정했다. 따라서 실행파일을 과학 소스 HEAD 하나로만 표현하지 않는다. 빌드·객체·아카이브·동적 라이브러리 영수증을 보존했다.
- 실제 WRF RK3는 `time_integration_scheme=0`; ARK는 selector 6과 IMEX split mode 3이다. ARK의 다른 실험 옵션을 RK3 대용으로 사용하지 않았다.
- RK3 `time_step_sound=4`의 단계별 소스텝 수는 1·2·4이며 소시간간격은 각각 h/3·h/4·h/4이다. 600초에서 200·150·150초다.
- 출력은 양쪽 모두 6시간 간격, 파일당 한 프레임, 시작 포함 21개다. 자료동화 목적함수·수반·궤적 그래프 보존은 실행하지 않았다. Newton에 필요한 AD JVP는 유지한다.
- MPI 1 rank, 계산 스레드 관련 환경값은 1로 고정했다. 실제 스냅샷에는 주 계산 스레드 외에 잠든 보조 스레드가 있다. 이를 MPI 스레드 지원 수준의 인증으로 해석하지 않는다.

ARK 후보는 Newton 절대 1e-9·상대 0·최대 40회, Krylov 1e-7·최대 100회·restart 30, 내부 FP64 연속 전달을 사용한다. 실패 시 종료하며 다른 적분법으로 자동 전환하지 않는다. 공식 RK3 음파 필터와 ARK의 암시적 발산 처리(kdamp=0.2)는 다른 정책이다. 이 차이는 숨기거나 성능을 맞추기 위해 변경하지 않았다.

## RK3 실제 결과

세 실행 모두 종료 코드 0, 예상 대시간스텝 수와 일치, 실패 표식 없음, 남은 소유 프로세스 없음이다. 같은 입력 해시 외에 **실제 t=0 history의 21개 상태·기본장·좌표 배열과 8개 전역 속성**이 수치적으로 정확히 일치한다. 부호 0은 같은 수치값으로 취급한다. 모든 저장 시각의 여섯 예보변수는 유한값이며 총 온위·기둥질량·층두께·총압이 양수다. 이는 출력 시각의 검사이며 모든 내부 단계의 점별 검사를 뜻하지 않는다.

| RK3 간격 | 대시간스텝 | 전체 wall time | 표본 최대 프로세스 트리 RSS |
|---:|---:|---:|---:|
| 600초 | 720 | 104.982794초 | 516,259,840 bytes |
| 300초 | 1,440 | 203.534168초 | 552,173,568 bytes |
| 150초 | 2,880 | 390.421281초 | 516,456,448 bytes |

시간은 같은 출력·종료 관찰 조건의 전체 경로 값이다. RSS는 주기적으로 관찰한 값이며 정확한 운영체제 최대 RSS가 아니다. 각 조건은 한 번의 실행이므로 반복 실행의 시간 분산은 측정하지 않았다.

5일 끝값의 150초 해 대비 RMS는 아래와 같다. **150초 해는 정확해가 아니라 비교 대상**이다. U 주기 중복면과 W·PH 고정 하단은 제외하고 V 물리 벽과 W·PH 동적 상단은 포함한다. 온위는 건조 T+300 K이며 기온이 아니다.

| 변수 | 단위 | 600−150초 RMS | 300−150초 RMS |
|---|---|---:|---:|
| U | m/s | 0.0276937918 | 0.0146145661 |
| V | m/s | 0.0334667490 | 0.0150268890 |
| W | m/s | 0.000185172865 | 0.000106766041 |
| PH | m²/s² | 2.16865416 | 1.30218117 |
| T | K | 0.00960317752 | 0.00436942743 |
| MU | Pa | 4.39704629 | 2.65875919 |
| 총압 P+PB | Pa | 1.94870976 | 1.17756436 |

W의 같은 방법 내부 간격 차이는 600/300초에서 9.33748e-5 m/s, 300/150초에서 1.06766e-4 m/s로 **단조 감소하지 않는다**. 형식 차수나 수렴한 RK3 기준해를 주장하지 않는다. 필터 정책의 시간간격 의존성도 향후 해석에 포함한다.

5일의 건조질량 상대 변화는 세 조건에서 약 1e-10 규모, 질량가중 온위 변화는 약 1e-7–1e-6 K 규모다. 이는 진단값이며 감쇠·확산이 있는 계산에 엄밀한 에너지 보존을 요구한 결과가 아니다. 파동 진단은 zonal mode 1의 진폭·위상·coherence를 정렬 없이 계산한다. 서로 다른 단위의 최대차를 하나의 크기 순위로 합치지 않는다. 상대 RMS의 분모가 작은 경우는 별도 표시한다.

## ARK 관찰기 시험의 중지와 남은 실행

첫 ARK600 시도에는 `WRF_SDIRK3_RHS_COUNT=1`이 포함됐다. 소스 확인 결과 이 설정은 호출 수만 세는 것이 아니라 **매 RHS마다 전체 입력을 FP32로 변환하고 FNV 해시를 계산**한다. RK3 경로에는 이 C++ RHS 관찰 비용이 발생하지 않는다. 따라서 해당 실행은 공정한 성능 표본이 될 수 없다.

그 시도는 수용 4스텝·수렴한 암시적 단계 13개 이후 약 290.5초에 명시적으로 중지했다. 원래 종료 코드 1과 KeyboardInterrupt, 소유 프로세스 정리 기록을 그대로 보존한다. 별도 중지 사유는 `measurement_setup_aborted`다. **ARK의 수치적 실패·600초 불안정·5일 실행시간으로 분류하지 않는다.** 해당 t=0 게이트는 통과했으나 완주한 ARK 장은 없다.

후속 `forecast_manifest_lean.json`은 RHS_COUNT만 제거한다. 초기장·실행파일·방정식·필터·Newton/Krylov 설정은 바꾸지 않으며, 기존 시도 디렉터리를 덮어쓰지 않는다. 이 lean 실행은 아직 시작하지 않았다. 관찰기 시험으로 장시간 자원 사용 가능성이 드러났으므로, 사용자에게 5일 장시간 실행 또는 우선 6시간 점검의 자원 범위를 질의한 상태다. 응답 없이 기존 한도를 연장하지 않는다. 관찰기 시간을 lean 실행시간으로 외삽하지 않는다.

## 변경과 검증

기존 `tools/benchmark_wrf_accuracy_cost.py`를 확장해 계획의 격자·시간창, t=0 history 출처, 공통 기본장, 총압, 건조 온위, 연직·경계·최대차 위치, 파동 및 질량 진단을 지원했다. 과학 생산 소스·공개 ABI·기본 허용오차는 수정하지 않았다.

Graphify의 변경 전·후 분석 그래프를 해당 worktree와 정확한 분석기 해시에 연결했다. 최종 분석기 SHA-256은 `9fc8475c33194f146f59ad8dc5e6ff394564599da0ca68fcc85404b0702aa2d4`이다. AST는 Python 분석기만 다루며 Fortran 호출·수치 정확성은 증명하지 않는다. Registry와 관련 Fortran/C++ 계약은 원문으로 별도 확인했다.

합성 NetCDF 회귀 9개와 Ruff 검사를 통과했다. 기존 16³·240초 자료의 공통 지표 750개도 재분석 결과가 동일했다. 기존 모델 실행을 반복한 것은 아니다. **이번에는 실제 표준 초기장 생성 1회와 RK3 5일 계산 3회, 중지된 ARK 시도 1회를 수행했다.** 같은 설정의 RK3 기준장은 확보했으나 완주 ARK와의 장·시간 비교는 아직 수행하지 못했다.

## 근거와 다음 행동

[근거 묶음](evidence/standard_forward_rk3_baseline/evidence.zip)과 [목록·한계](evidence/standard_forward_rk3_baseline/README.md)에 실행·빌드·입력·설정·분석 영수증, CSV, 그림, 코드 및 해시를 모았다. 전체 native NetCDF와 실행파일은 외부 근거 디렉터리에 보존하며 ZIP에는 포함하지 않는다. ZIP의 재검산은 저장된 분석 수치와 영수증을 확인하는 것이며 원배열 재차감과 다르다.

자원 범위가 정해지면 lean ARK를 같은 초기장에서 연속 실행한다. 실행 중 실제 단계 실패가 생기면 첫 실패를 보존하고 CFL·풀이·상태 허용성 중 어느 경계인지 좁힌다. 완료된 작은 수반·복원 검사, R1 smoke 반복, 새 자료동화·습윤·플랫폼 확장을 이 비교 앞에 추가하지 않는다.
