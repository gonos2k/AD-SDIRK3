# 표준 ARK600 비용 점검과 개선 후보의 미채택

작성 시각: 2026-10-24 22:13:24 JST (UTC+09:00)

PR #319 검토의 두 P2를 수정하고, 표준 `em_b_wave`에서 비용을 한 번 좁혀 조사했다. CPU MGS 벡터 갱신의 융합 후보를 빌드·검사·native 대조했지만 **채택하지 않았다**. 커널 측정의 개선이 전체 모델 비용 개선으로 이어졌다는 근거를 얻지 못했고, 사전에 정한 짧은 대조의 공개 출력 바이트 일치 조건도 충족하지 못했다. 생산 Newton 소스는 원래 버전으로 되돌렸다. 허용오차·물리식·필터·JVP·ABI는 최종 변경하지 않았다.

## 체크리스트

| 항목 | 결과 |
|---|---|
| `wave_mode1=true` 예외 | 공통 입력 해석으로 수정, 분석기 검사 10/10 |

| 표준 격자·600초의 좁은 비용 점검 | 1스텝 실행·집계·스택 표본 확보, RC0 |
| 제한적인 비용 개선 | MGS 융합 후보를 검증 후 미채택, 실제 비용 개선은 미완료 |
| 최종 코드의 Krylov 회귀 | 기존 시험에 재직교화·breakdown 보강, 기준 아카이브에서 49/49 |
| ARK600의 연속 5일 및 300/150초 민감도 | 미실행·미완료 |
| 새 물리 정확도·동일 정확도 비용 수용 | 기준 미확정, 합격 주장 없음 |

기존 작은 240초 전방·수반·쌍둥이 사례와 quiet 6시간 근거는 보존했다. MPI 종료 원인 조사는 별도 미해결 상태다.

## 두 P2 수정

`tools/benchmark_wrf_accuracy_cost.py`의 `_wave_mode1_fields()`를 loader와 wave 분석이 함께 사용한다. `True`는 기본 T/W/P 필드, `False`와 비활성 설정은 미사용으로 해석한다. 매핑형 설정을 유지하고 지원하지 않는 활성 형식은 명시적으로 거부한다. `True`와 기본 필드 매핑의 전체 결과 일치, `False`의 wave 미생성 및 기존 장·민감도 값 보존을 검사했다. 모델을 재실행해 고친 항목은 아니다.

`.github/ci/expected_ctest_names.txt`를 CMake 등록에 맞췄다. 정적 검사는 MPI 1/2/4 확장과 현재 없는 선택 소스의 제외를 명시해 130개 일치를 확인한다. **새 CMake configure 또는 구성된 CTest 목록 검증을 수행했다는 뜻은 아니다.** 과거 129개 시험 증거의 재사용 guard는 완화하지 않았다.

## 비용 점검

질량 격자 40×80×64, 100 km, h=600초의 동일 표준 건조 설정으로 첫 1스텝만 실행했다. 공통 입력, 초기화 이후 상태, 내부 FP64 전달, strict 풀이 기준을 유지했다. 자료동화 궤적은 요청하지 않았다. 이번 한정 진단에는 `debug=0, solver_telemetry=true`를 명시했고 `/usr/bin/sample`을 한 번 붙였다. 일반 전방의 진단 OFF 정책은 바꾸지 않았다.

실행은 RC0, 수용 스텝 1개·수렴 단계 3개, AD JVP 240회·FD 0회였다. 샘플러의 15초 요청에서 main-thread 가중 표본 9,689개를 트리의 자식 가중치와 분리해 계산했다.

| 서로 겹치지 않는 main-thread 표본 | 수 | 비율 |
|---|---:|---:|
| JVP 경로 | 6,664 | 68.78% |
| 전처리 경로 | 518 | 5.35% |
| 그 밖의 FGMRES | 2,339 | 24.14% |
| 그 밖의 단계/RHS | 168 | 1.73% |

이는 **스택 표본 비중**이며 정확한 함수별 wall time이 아니다. JVP 밖 FGMRES 표본에서 add/mul leaf가 1,369개였지만, 이를 특정 MGS 소스 한 줄의 비용이라고 단정하지 않았다. 포함 관계가 있는 copy/index-select 통계를 더하지 않았다. 원시 샘플과 재계산 parser를 보존했다.

## 후보와 실제 대조 결과

후보는 GMRES/FGMRES의 첫 MGS·DGK 보정 네 곳에서 `w - h*v`를 CPU FP32/FP64의 out-of-place `addcmul`로 계산했다. 다른 장치·자료형은 원래 식을 사용했다. 투영 순서, H 갱신, variable-PC의 Z, DGK 문턱, 실제 `b-Ax` 잔차와 종료 조건은 유지했다. 실수 산술에서는 같은 식이지만 부동소수점 반올림은 달라질 수 있다.

같은 설치 Torch 2.10.0·CPU 한 스레드의 커널 측정은 FP32 1.42배, FP64 1.60배였다. dtype·forward/reverse AD 소규모 대조와 후보 아카이브의 diagnostics 24/24, fixed-trajectory derivative, 보강 FGMRES 49개가 통과했다. **이 커널 수치는 native 예측 속도 향상이 아니다.** 최초 커널 측정 harness는 inline이었으며 원 스크립트가 보존되지 않아, 그 수치를 독립적인 성능 수용 근거로 사용하지 않는다.

다음으로 같은 입력·namelist·환경에서 샘플러 없이 기준/후보 각 1스텝을 실행했다. 둘 다 집계 계측 ON이며 일반 quiet 성능시험과 구분한다.

| 항목 | 기준 | 후보 |
|---|---:|---:|
| 종료·스텝·수렴 단계 | RC0·1·3 | RC0·1·3 |
| AD/FD JVP | 240/0 | 240/0 |
| 단계별 Krylov 반복 | 각각 29, 43 | 각각 29, 43 |
| 전체 단조 경과시간 | 48.534517초 | 56.080655초 |
| RSL main-step 시간 | 46.805370초 | 54.123610초 |
| 계측된 JVP 시간 | 31.300490초 | 38.428560초 |

양쪽 실제 Krylov 잔차는 같은 1e-7 기준 이하, 수렴한 Newton scaled-RMS 잔차는 같은 1e-9 기준 이하였다. 반복수는 같지만 잔차 수치까지 같지는 않았다. 시작 NetCDF는 전체 바이트 일치했다. **600초 끝값**의 174개 숫자 변수 중 V/W/PH는 다음 최대차가 있었고 나머지는 일치했다.

| 변수 | 끝값 최대 절대차 |
|---|---:|
| V | 2.3283064365e-10 m/s |
| W | 1.4551915228e-11 m/s |
| PH | 3.7252902985e-9 m²/s² |

이 작은 차이만으로 방정식 결함이나 물리적 부적합을 주장하지 않는다. 그러나 이번 후보의 사전 공개 출력 일치 gate에는 미충족이고, 이 단일 대조에는 비용 감소 근거도 없다. 결과를 본 뒤 gate를 완화하거나 반복 실행을 추가해 통과를 찾지 않았다. 후보 소스·패치·실행파일 해시·실패 판정을 보존하고 **생산 변경은 원복**했다. 단일 계측 실행의 시간 차이를 일반적인 감속이나 그 원인의 증명으로 해석하지 않는다.

## 최종 검증과 열린 범위

최종 생산 Newton SHA-256은 기준과 같은 `507d1ef403948b44c4727ab5297f4012d8b985e997eb4bcaad9aa80d7071d769`이다. 보강한 `FGMRES_Contract`는 이 기준 아카이브에서 다시 49/49 통과했다. FGMRES 시험은 비어 있지 않은 identity 전처리와 적용 횟수를 검사하므로 GMRES fallback만 검사하는 우회를 피한다. FP32/FP64의 재직교화와 zero-operator breakdown을 독립 FP64 `b-Ax`와 실패 상태로 판정한다.

분석기 10개 검사와 명시적으로 선택한 Ruff E4/E7/E9/F 검사는 통과했다. 전체 규칙 lint는 기존 항목을 포함한 스타일 진단 9개가 있어 clean이라고 주장하지 않는다. 전체 CTest나 새 GitHub CI 실행 결과로 확대하지 않는다. 처음 Python 검사를 잘못된 import 경로로 호출한 기록과 올바른 직접 호출의 통과 기록도 각각 보존했다.

이번 새 native 시도는 **3회, 모두 RC0, 총 3개 모델 스텝**이다. 새 RK3 실행이나 새 6시간·5일 ARK 실행은 하지 않았다. 같은 setup의 RK3 장·비용 비교는 [보존된 quiet 6시간 대조](<(202610241655)_quiet_forward_diagnostics_native_validation.md>)를 재사용한다. 그 ARK/RK3 RSL 비율 약 443.30배는 해결되지 않았고, 이번 1스텝 후보를 그 대조와 섞지 않는다.

ARK600의 5일은 현재 비용에서 10시간 이상이 예상되어 앞서 정한 건별 6시간 실시간 한도를 넘을 수 있다. 18시간 야간 한도와 단기 비용 검증만 진행하는 선택을 문의해 둔 상태이며 응답을 실행 승인으로 가정하지 않는다. 새 물리 정확도 기준도 미확정이다. 예측장 거리를 보고하는 것과 정확도 합격·동일 정확도 속도비는 구분한다. ARK600의 연속 5일, 이후 300/150초와 기존 RK3의 비교, 실제 비용 개선은 미완료로 남긴다.

Graphify의 기존 20개 소스 핀을 확인하고 분석기 변경 후 그래프를 생성했다. 후보의 변경 후 그래프와 생산 소스 복구 후의 최종 바인딩을 구분한다. 시험 호출·경계 및 Fortran처럼 추출하지 않은 경로는 원문 확인과 명시적 공백으로 기록했다. 그래프를 수치 정확성 증거로 사용하지 않는다.

[실행·소스·부정 결과·재검산 근거](evidence/forward_cost_profile/README.md)에 원시 샘플, 600초 native 출력, 명령·빌드·라이브러리 해시, 회귀 결과와 체크리스트를 보존했다. 기존 사용자 작업 트리는 수정하지 않았다.

Green·Red 팀의 최종 검토에서 보고 수치·시간창 구분·후보 미채택과 생산 소스 복구를 확인했다. Green 팀은 정확한 작업 트리 경로에서 복구 후 해시와 빈 Newton diff를 다시 확인했다. 원시 배열 대조·소스 검토·정적 목록 확인을 각각의 범위로 유지한다.
