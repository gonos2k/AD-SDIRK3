# JVP 주기 선택의 순열 교체와 표준 첫 스텝 비용 감소

작성 시각: 2026-10-24 23:36:56 JST (UTC+09:00)

표준 `em_b_wave`의 600초 JVP 경로에서 주기 방향의 값 선택을 같은 순열의 `torch::roll`로 바꿨다. 사전에 고정한 A–B–B–A의 첫 스텝 대조 네 번이 모두 정상 종료했고, 공개 출력·표시된 실제 잔차·풀이 작업량이 일치했다. 이 한 블록에서 **RSL 적분시간 중앙값 17.7902%, JVP 호출당 계측시간 중앙값 18.8131% 감소**를 확인해 해당 변경을 채택했다.

이는 집계 계측 ON의 첫 600초·CPU 사례 결과다. 일반 quiet 실행, 6시간·5일, 동일 정확도 비용 우위를 새로 인증한 결과가 아니다. PR #320의 두 P2와 미채택 MGS 검토는 종료 상태로 보존하며, MGS 후보를 다시 적용하지 않았다.

## 한 곳만 바꾼 이유와 식

`wrf_sdirk3_phi_horizontal.h::periodic_select`의 기존 선택은 `out[i] = q[(i+offset) mod n]`이다. `roll(q, -offset, dim)`은 같은 원소를 같은 위치로 보낸다. 실수 산술의 재배열이 아니라 **현재 값·접선의 순열 복사 방식**을 바꾸는 것이다. `offset`을 int64로 바꾼 뒤 부호를 반전해 `INT_MIN`도 안전하게 처리한다.

매번 만들던 `arange`·나머지 인덱스와 열 방향 `index_select`를 제거했다. 현재 상태 q에 대한 roll은 호출마다 수행하며 결과를 캐시하지 않는다. 따라서 압력·밀도·질량·상태 의존 기하를 고정하거나, 상태 의존 계수의 미분을 버리지 않는다. 이 선형 순열의 JVP는 같은 순열을 방향에 적용하고 VJP는 역순열을 cotangent에 적용한다.

대칭 Y의 `reflected_select`, 차분 계수·순서·정밀도·경계 소유 규약·수송·확산·감쇠는 유지했다. Newton/Krylov 식·허용오차·전처리·JVP 방식·ABI·자료동화 기록 정책도 바꾸지 않았다. 새 옵션이 없으며 일반 전방의 집계/디버그 OFF 기본 설정은 유지한다.

## 기존 표본은 후보를 좁히는 근거다

PR #320의 원시 표본을 재사용했다. JVP 버킷의 exclusive 표본은 6,664개이며, 6,662개는 RHS callback 하위에 있다. 고정 `arange`·`remainder` 생성은 self 표본이 합계 4개뿐이다. **고정 인덱스 생성 자체를 지배 병목이라고 주장하지 않는다.** 값 gather 하위는 334개, 그중 periodic selection은 291개다. 포함 관계가 있는 수치를 합산하지 않는다.

이번 후보는 그 반복 선택의 비용을 줄인다. 전체 JVP 병목을 해소한 것은 아니다. 같은 설치 Torch 2.10.0·CPU 한 스레드의 80×65×40 PH 형상에서 여섯 선택을 수행한 직접 dual 대조는, FP32/FP64·연속/strided 네 경우 값·접선·역기울기가 일치했고 부분 연산 시간은 약 4.49–5.62배 개선됐다. 정확한 harness와 결과를 보존했다. 이 수치를 전체 모델 속도로 사용하지 않았다.

## 실행 전에 고정한 규약

`protocol.json`은 소스 변경 전에 생성해 SHA-256을 고정했다. 비용 대조는 기준 A0 → 후보 B0 → 후보 B1 → 기준 A1의 **정확히 네 번**, 재시도 없이 수행한다. 모두 질량 격자 40×80×64, 100 km, h=600초, 원래 초기장부터 첫 600초를 계산한다. 서로 다른 네 첫 스텝이며 연속 40분 적분 결과가 아니다.

같은 입력·namelist·rank 1·요청 thread 설정·컴파일러/libtorch/MPI/netCDF 스택·출력을 사용했다. `debug=0, solver_telemetry=true`를 양쪽에 똑같이 적용했다. 새 stack sampler나 RHS_COUNT, 자료동화 궤적 저장은 활성화하지 않았다. owned-process 정리·실시간 상한·메모리/디스크 한도·초기상태 gate도 동일하다.

수치 조건은 순열 변경에 맞는 정확한 값·미분 일치, 공개 출력 바이트 일치, 동일한 표시 실제 잔차·반복/JVP 작업량과 기존 허용오차였다. 비용 조건은 RSL 중앙값 3% 이상 감소, 양쪽 대응쌍 각각 1% 이상 감소, JVP 호출당 중앙값 5% 이상 감소다. 결과를 보고 조건·순서·횟수를 바꾸지 않았다. 산술 순서를 바꾸는 다른 후보에 이 비트 조건을 자동 적용한다는 뜻은 아니다.

## 재빌드와 집중 회귀

인라인 헤더의 직접 의존자는 Tile 구현과 PH 커널 시험이다. 변경된 Tile만 원래 ad3 C++ 아카이브의 사본에서 교체하고, 같은 Fortran·헤더/라이브러리 스택으로 별도 실행파일을 링크했다. **아카이브의 Tile 멤버만 변경**됐고 원래 기준 실행파일은 보존했다. ABI 변경은 없다.

다음 네 시험이 후보 아카이브에서 통과했다.

- PH kernel: 기존 물리 oracle/차분/VJP와 새 정확 순열 검사. FP32/FP64, 연속/비연속, 축 0/2, singleton, 0·±1/2/3·wrap·INT_MIN 이동량, 다른 상태와 두 접선 방향·역기울기를 확인했다.
- PH coordinate: native Tile 경로의 좌표·oracle·AD 검사.
- Solver diagnostics: 24/24.
- Fixed trajectory derivative: 통과.

Newton 소스는 여전히 기준 `507d1ef4…`이고 PR #320의 49개 Krylov 회귀와 통과한 CI는 재사용했다. 이번 네 검사를 새 전체 CTest 실행이라고 부르지 않는다.

대조 종료 후에는 forward-dual 시험에서 같은 primal을 고정한 채 두 방향만 바꾸도록 시험을 더 명확하게 했다. 이 최종 PH kernel 시험만 다시 빌드·실행해 통과했다. 생산 헤더·실행파일·수용 조건은 같으며 native 네 실행이나 다른 회귀를 반복하지 않았다.

모두 RC0·수용 스텝 1개·수렴 암시적 단계 3개였다. 단계별 Krylov 반복수는 각각 29·43회로 같았다. 기존 계측의 AD 선택/명시적 FD 선택 카운터는 각각 240/0이었다. **내부 fwAD→FD fallback의 별도 카운터를 이번 실행에서 독립적으로 추출한 것은 아니다.** 선택 구현·방식은 유지했고 새 연산의 direct forward-dual 일치를 검사했다. 이 분기 카운터를 추가적인 fallback-free 인증으로 확대하지 않는다.

표시된 실제 Krylov 잔차와 Newton scaled-RMS 잔차는 네 실행에서 일치했고 기존 1e-7·1e-9 기준을 충족했다. 시작·600초의 여덟 NetCDF가 같은 시각의 기준 파일과 전체 바이트 일치했다. 3개 비교 경로×2시각×174개 숫자 변수의 **1,044개 배열 대조**도 유한값·정확 일치했다. 이는 공개 FP32 출력의 검사이며 모든 내부 FP64 배열을 새로 저장한 주장은 아니다.

A0/B0, A1/B1의 RSL 감소율은 각각 **14.3333%, 21.2559%**다. 기준 RSL 중앙값은 157.735390초, 후보는 129.673950초다. 후보 두 RSL 값은 11.2467초 차이가 나며 기준 차이 0.39812초보다 크다. 두 쌍과 변동 폭을 함께 보고하고 평균값 하나만으로 일반적인 성능을 단정하지 않는다.

이번 기준 실행 자체가 과거 한 쌍의 첫 스텝 측정보다 약 세 배 느렸다. 원인을 분리하지 않았으므로 과거 시간과 이번 후보 시간을 나눠 새 성능비를 만들지 않는다. 사전 고정된 이번 블록의 수용 조건을 충족했다는 결론으로 제한한다. 각 JVP/나머지 구간의 차감을 특정 소스 한 줄의 인과적 비용으로 해석하지 않는다.

## RK3와 장시간 목표는 열린 상태다

동일 setup의 RK3 예측장·비용은 [보존된 quiet 6시간 대조](<(202610241655)_quiet_forward_diagnostics_native_validation.md>)와 [5일 RK3 기준](<(202610241316)_standard_forward_rk3_baseline_and_ark_pending.md>)을 재사용한다. 이번에는 새 RK3 실행이나 새 6시간·5일 ARK 실행을 하지 않았다. 따라서 **새 RK3 대비 속도비는 없으며**, 기존 약 443.30배의 6시간 RSL 격차가 해결됐다고 주장하지 않는다. 이 비율에 17.79%를 곱해 장시간 개선값으로 사용하지 않는다.

ARK600의 연속 5일·300/150초 민감도와 새 물리 정확도/동일 정확도 비용 수용은 미완료다. 앞서 정한 실시간 한도를 넘을 수 있는 5일 실행의 자원 범위에 대한 응답은 아직 없어 자동 시작하지 않았다. 비용 개선을 완벽하게 마칠 때까지 5일 비교를 미루는 조건을 새로 추가하지 않는다. 자원 범위가 정해지면 기존 RK3 자료와 연속 5일 전방 비교를 진행하는 별도 완료 목표다. 기존 작은 수반·쌍둥이 완료 상태는 그대로 유지한다.
